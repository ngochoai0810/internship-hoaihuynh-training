# Alembic Setup And First Migration

## Goal

Use Alembic to manage database schema changes for the SQLAlchemy ORM models.
This replaces `Base.metadata.create_all()` as the main workflow for the app
database.

## Key Ideas

- `create_all()` creates missing tables but does not track schema history.
- Alembic stores schema changes as migration files with `upgrade()` and
  `downgrade()`.
- `--autogenerate` compares the database schema with `target_metadata`.
- Autogenerated migrations must be reviewed before applying them.

## Setup

`orm_migrations/alembic.ini` points to the local SQLite database:

```ini
sqlalchemy.url = sqlite:///./app.db
```

`alembic/env.py` imports all models through `orm_migrations.src.models` before
setting `target_metadata`:

```python
from orm_migrations.src.models import Base

target_metadata = Base.metadata
```

Run Alembic commands from `orm_migrations/`. The old Day 21 `app.db` was backed
up before generating the first migration.

```powershell
cd orm_migrations
python -m alembic init alembic
python -m alembic revision --autogenerate -m "create user house prediction history tables"
python -m alembic upgrade head
python -m alembic current
python -m alembic history
python -m alembic downgrade -1
python -m alembic upgrade head
```

## First Migration

The first generated revision is:

```text
54b4c66d53f3_create_user_house_prediction_history_.py
```

It creates the current project tables:

- `houses`
- `users`
- `prediction_history`

`prediction_history.user_id` has a foreign key to `users.id`. The
`downgrade()` drops `prediction_history` before parent tables to avoid
foreign-key errors.

## Verification

- `alembic upgrade head` created `alembic_version`, `houses`, `users`, and
  `prediction_history`.
- `alembic current` returned `54b4c66d53f3 (head)`.
- `alembic downgrade -1` removed the app tables and kept `alembic_version`.
- Running `upgrade head` again worked.
- `pytest orm_migrations` passed: `5 passed`.

## Notes

- Missing model imports can make Alembic generate an incomplete migration.
- Alembic may treat a column rename as drop plus add.
- SQLite has limited `ALTER TABLE` support, so complex future migrations may
  need `op.batch_alter_table(...)`.
